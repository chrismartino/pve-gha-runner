Self-hosted GitHub Actions runners on Proxmox, in LXC containers.

Shell scripts that create unprivileged Ubuntu 24.04 LXC containers on Proxmox VE and register them as GitHub Actions runners. Run a long-lived runner, or opt in to an ephemeral pool where every job gets a fresh container.

Get started View on GitHub

Two ways to run

Persistent runner default

Each run of the script creates one long-lived container that registers as a normal runner and keeps handling jobs until you remove it. It's the simplest setup. Run the script again for more runners, up to MAX_RUNNERS (default 3) per repo or org.

Workspaces, caches and installed tools carry over between jobs.

Ephemeral pool opt-in

Set EPHEMERAL_RUNNER=true. Each container runs exactly one job, powers off, and a Proxmox hookscript destroys it and creates a fresh replacement, so there is always a clean runner.

Needs a hookscript and a per-repo config file. No state carries between jobs.

How the ephemeral pool works: the container registers with --ephemeral, a one-shot systemd unit runs the job and powers it off, the post-stop hookscript destroys it and runs the create script again, and a per-container flap guard stops a broken registration from respawning in a loop.

Features

GitHub App auth

Signs a short-lived JWT, exchanges it for an installation token, and requests the registration token. No long-lived PAT is stored or passed into containers.

Unprivileged containers

Built for Proxmox VE 9 (LXC 6, cgroup v2) so Docker can work inside unprivileged containers.

Repo or org runners

Register against one repository, or against an organization with GITHUB_SCOPE=org and a narrower App permission.

Multi-repo

One hookscript serves every repo. Each container is tagged repo-<slug> and reads its own config, with its own MAX_RUNNERS cap.

Extra dependencies

Point EXTRA_INSTALL_SCRIPT at a script to install Docker or any CLIs your jobs need. An example is included.

Verified runner download

Resolves the latest actions/runner release at run time and checks it against GitHub's published SHA-256 when available.

Quick start

You need Proxmox VE 9, openssl and curl on the host, and a GitHub App installed on your repository. Put the scripts on the host, in /root/scripts:

git clone https://github.com/chrismartino/pve-gha-runner.git
cd pve-gha-runner
install -d -m 700 /root/scripts
install -m 700 create-pve-lxc-gha-runner.sh /root/scripts/

Persistent runner

This is all you need. The script prompts for the App ID, the private key path and owner/repo if you don't set them:

cd /root/scripts
GITHUB_APP_ID=123456 \
GITHUB_APP_PRIVATE_KEY_PATH=/root/my-app.private-key.pem \
OWNERREPO=someorg/somerepo \
./create-pve-lxc-gha-runner.sh

The new container shows up under your repo's Settings → Actions → Runners as a normal runner.

Ephemeral pool

Three extra steps. The README has the details, including log rotation.

  1. Install the hookscript where Proxmox can run it: 
    install -m 700 gha_runner_hookscript.sh /var/lib/vz/snippets/
  2. Create a per-repo config at /etc/gha-runner/<owner>-<repo>.conf (lowercase, / replaced by -) and make it root-only (chmod 600): 
    GITHUB_APP_ID="123456"
GITHUB_APP_PRIVATE_KEY_PATH="/root/my-app.private-key.pem"
OWNERREPO="someorg/somerepo"
  3. Create the first container by hand with ephemeral mode on. Every container it creates after that inherits the setup: 
    cd /root/scripts
EPHEMERAL_RUNNER=true \
GITHUB_APP_ID=123456 \
GITHUB_APP_PRIVATE_KEY_PATH=/root/my-app.private-key.pem \
OWNERREPO=someorg/somerepo \
./create-pve-lxc-gha-runner.sh

Organization runners

Add GITHUB_SCOPE=org and GITHUB_ORG=someorg instead of OWNERREPO, to either mode. The App then needs the organization permission "Self-hosted runners: Read and write". See Organization-level runners.

Releases

Install from a tagged release. Releases from 1.2.0 on include a SHA256SUMS file and build provenance attestations, so you can check what you downloaded:

sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <file> --repo chrismartino/pve-gha-runner

To update an existing installation, see Upgrading.

Security notes

Use these runners with private repositories. On a public repository, a pull request from a fork can run arbitrary code on a self-hosted runner. Ephemeral containers limit the damage but do not make that safe.
  • The App's private key stays on the Proxmox host and is never copied into a container.
  • The registration token is pushed in as a file, so it does not appear in host ps output.
  • Persistent runners keep their state between jobs. Only the ephemeral pool starts every job from a clean container.
  • The scripts run as root on your Proxmox host. Read them before you run them.

To report a vulnerability, use the repository's Security tab.
